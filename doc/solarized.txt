1. INTRODUCTION                                        *solarized-introduction*

solarized is a quiet take on the Solarized palette (Ethan Schoonover). Code uses a
single foreground color, except strings (green), functions (blue), types
(yellow) and constants/literals (orange). Keywords and comments are told
apart by style (bold keywords; italic comments a step dimmer than the code,
still WCAG AA), not by hue.
Red is reserved for errors and git deletions; there is no purple or pink.
Color is otherwise used only where it carries meaning:

  - git: add = green, change = blue, delete = red
  - diagnostics: error, warn, info, hint, ok
  - LSP completion and symbol kinds (blink.cmp, dropbar)
  - file icons (mini.icons)
  - search and TODO/FIXME/NOTE markers

Highlights are compiled to LuaJIT bytecode and cached, so a cached load takes
a few milliseconds.

2. USAGE                                                      *solarized-usage*

>lua
    require("solarized").setup({})   -- optional
    vim.cmd.colorscheme("solarized")
<
                                  *solarized* *solarized-light* *solarized-dark*
  solarized         follows 'background' (or the `variant` option)
  solarized-light   always light
  solarized-dark    always dark

Neovim detects the terminal background at startup. When you use `solarized`,
the theme follows the terminal and switches when 'background' changes.

3. CONFIGURATION                                             *solarized-config*

Defaults:
>lua
    require("solarized").setup({
      variant = "auto",        -- "auto" | "light" | "dark"
      transparent = false,
      terminal_colors = true,
      dim_inactive = false,
      muted_comments = false,
      mono = false,            -- all code in fg
      float = { solid = false },
      styles = {
        comments = { italic = true },
        keywords = { bold = true },
        functions = {}, variables = {}, strings = {},
        types = {}, constants = {}, operators = {},
      },
      integrations = {
        blink = true, dropbar = true, gitsigns = true, grug_far = true,
        lazy = true, mason = true, mini = true,
        semantic_tokens = true, statusline = true, treesitter = true,
      },
      cache = true,
      on_colors = nil,         -- fun(colors, variant)
      on_highlights = nil,     -- fun(hl, colors, variant)
    })
<
                                                          *solarized-on_colors*
on_colors(colors, variant)
    Change the palette before highlights are built. Keys: `bg`, `fg`, `red`,
    `orange`, `yellow`, `green`, `cyan`, `azure`, `blue`, `accent`,
    `surface1`, `surface2`, `surface3`, `select`, `border`, `muted`, `comment`,
    `bg_dim`, `bg_float`, `code.{string,func,type,constant}`,
    `git.{add,change,delete}`, `diag.{error,warn,info,hint,ok}`.

                                                               *solarized-mono*
mono
    When true, strings, functions, types and constants use `fg` like the
    rest of the code.

                                                      *solarized-on_highlights*
on_highlights(hl, colors, variant)
    Change or add highlight groups. `hl` maps group names to
    |nvim_set_hl()| specs, with colors as "#rrggbb" strings.

The compiled cache is keyed by a hash of your options, so changes take effect
on the next `:colorscheme`. The hash covers function bodies but not captured
upvalues. If you change such a value, run |:SolarizedCompile|.

==============================================================================
4. COMMANDS                                                *solarized-commands*

                                                            *:SolarizedCompile*
:SolarizedCompile       Delete and rebuild the compiled cache, then reload.

                                                         *:SolarizedClearCache*
:SolarizedClearCache    Delete the compiled cache.

                                                             *:SolarizedExtras*
:SolarizedExtras [dir]  Write the Ghostty, Kitty and Lazygit themes to [dir]
                        (default: the plugin's `extras/` directory).

==============================================================================
5. API                                                          *solarized-api*

require("solarized").setup({opts})         Configure.
require("solarized").load({name})          Apply a colorscheme by name.
require("solarized").colors({variant})     Return the full palette.
require("solarized").highlights({variant}) Return the final highlight table.
require("solarized").compile()             Same as |:SolarizedCompile|.
require("solarized").clear_cache()         Same as |:SolarizedClearCache|.
require("solarized").extras({dir})         Same as |:SolarizedExtras|.

==============================================================================
6. EXTRAS                                                    *solarized-extras*

extras/ghostty/solarized-{light,dark}
    Copy to ~/.config/ghostty/themes/ and set:
    `theme = light:solarized-light,dark:solarized-dark`

extras/kitty/solarized-{light,dark}.conf
    Copy to ~/.config/kitty/{light,dark}-theme.auto.conf.

extras/lazygit/solarized-{light,dark}.yml
    Merge into config.yml, or append to LG_CONFIG_FILE.
